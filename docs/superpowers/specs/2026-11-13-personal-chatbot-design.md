# 개인용 챗봇 설계 문서

- 작성일: 2026-11-13
- 상태: 승인됨 (2026-11-13)

표기: **[사용자 결정]** 은 대화에서 사용자가 직접 정한 것, **[제안]** 은 작성자가 정한 것으로 사용자가 바꿀 수 있다.

## 1. 의도

휴대폰에서 혼자 쓰는 챗봇을 만든다. 사용자는 RPG 캐릭터를 만들듯 챗봇에게 인물 설정을 부여하고, 채팅앱 대화 내보내기 파일(txt)을 넣어 그 인물의 말투와 둘 사이의 기억을 입힌다. 챗봇은 그 인물로서 사용자를 대하고, 사용자의 개인 정보와 지난 대화를 기억하며, 앱을 열면 지난 대화를 바탕으로 먼저 말을 건다.

## 2. 목표, 비목표, 실패 조건

### 목표 (1차 버전)

1. **[사용자 결정]** 인물 설정: 캐릭터 시트(이름, 성격, 말투, 사용자와의 관계, 배경 설정)를 사용자가 작성하고 수정한다.
2. **[사용자 결정]** 첨부파일로 인물 만들기: 채팅앱 대화 내보내기 txt 파일에서 상대방의 말투, 자주 쓰는 표현, 둘 사이의 사건을 뽑아 캐릭터 시트 초안과 기억을 자동으로 만든다.
3. **[사용자 결정]** 사용자 정보 반영: 개인 정보, 이력서, 취미, 과거 이야기를 입력해 두면 챗봇이 이를 알고 대화한다.
4. **[사용자 결정]** 대화 기억: 지난 대화를 기억하고 이어간다.
5. **[사용자 결정]** 먼저 말 걸기: 앱을 열었을 때 챗봇이 지난 대화를 바탕으로 먼저 화제를 꺼낸다.
6. **[사용자 결정]** 인물은 처음에 한 명. 나중에 교체할 수 있어야 한다.
7. **[사용자 결정]** 앱 차원의 대화 주제 필터를 두지 않는다.

### 비목표 (1차 버전에서 만들지 않음)

- 앱을 닫았을 때 오는 알림 (2차. 6.5절의 분리 구조로 대비만 한다)
- 여러 인물을 동시에 두고 고르는 화면 (2차. 데이터는 인물별로 분리해 저장한다)
- 기기 간 자동 동기화, 로그인, 계정
- 음성, 이미지 주고받기
- **[제안]** PDF, 워드 파일 읽기. 1차는 txt 파일과 직접 붙여넣기만 받는다.
- AI 모델 자체를 다시 훈련시키는 것 (파인튜닝)

### 실패 조건 (기능이 돌아가도 실패로 본다)

- 인물이 설정과 다르게 일반 AI 비서 말투로 대답한다.
- 며칠 전 대화나 내보내기 파일 속 사건을 기억하지 못한다.
- 먼저 거는 말이 매번 비슷하거나 지난 대화와 무관하다.
- 개인 정보나 대화 기록이 AI 모델 호출 외의 경로로 기기 밖에 나간다.

## 3. 제약

- **서버 없음.** **[사용자 결정]** 모든 데이터는 휴대폰 브라우저 저장소에만 둔다. 기기 밖으로 나가는 것은 AI 모델 API 호출뿐이다.
- **AI 제공사 정책.** 앱은 필터를 넣지 않지만, 사용하는 AI 모델은 제공사의 이용 정책을 따른다. 이를 우회하는 장치(탈옥 문구 등)는 만들지 않는다. 모델이 답변을 거절하면 그 응답을 그대로 보여준다.
- **API 키.** **[사용자 결정]** 사용자가 본인 API 키를 설정 화면에 입력한다. 키는 기기에만 저장한다.
- **정적 호스팅 필요.** 홈 화면 설치에는 HTTPS 주소가 필요하다. 앱 파일(코드만, 데이터 없음)을 무료 정적 호스팅에 올린다. 이는 데이터를 보관하는 서버가 아니다.
- **브라우저 직접 호출.** AI 제공사가 브라우저에서의 직접 API 호출을 허용해야 한다. 구현 계획의 첫 작업에서 실제 호출로 확인한다. 불가하면 설계를 재검토한다.
- **혼자 쓰는 앱.** 내보내기 파일에는 상대방의 사적인 대화가 들어 있다. 공유, 배포, 타인에게 메시지를 보내는 기능은 만들지 않는다.
- 화면 언어는 한국어.

## 4. 검토한 접근

| 접근 | 장점 | 단점 |
|---|---|---|
| A. 홈 화면 설치형 웹앱, 서버 없음 | 가장 빠름, 운영비는 AI 사용료뿐, 아이폰과 안드로이드 모두 지원, 민감 자료가 기기에만 있음 | 닫힌 상태의 알림은 나중에 서버 추가 필요, 기기 변경 시 수동 백업 |
| B. 앱스토어용 정식 앱 | 알림 등 기기 기능이 자연스러움 | 개발 환경이 무겁고 등록비 필요, 스토어 심사 위험 |
| C. 웹앱 + 서버 | 처음부터 알림 가능, 기기 변경에 강함 | 서버 비용과 관리, 민감 자료가 서버에 올라감 |

**선택: A.** **[사용자 결정]** 혼자 쓰는 앱이고 자료가 민감하므로 기기 안에만 두는 쪽을 택했다.

## 5. 화면

화면은 네 개다.

```
[대화]                 [인물]                [내 정보]            [설정]
┌──────────────┐      ┌──────────────┐     ┌──────────────┐    ┌──────────────┐
│ 지수      ⚙ │      │ 이름: 지수    │     │ 기본 정보     │    │ API 키: ****  │
│              │      │ 관계: 대학 친구│     │ 이력서        │    │ 모델: [선택]  │
│ 어제 면접    │      │ 성격: ...     │     │ 취미          │    │ 백업 내보내기 │
│ 어땠어?      │      │ 말투: ...     │     │ 과거 이야기   │    │ 백업 가져오기 │
│      잘 봤어 │      │ 배경 설정: ...│     │ (자유 입력,   │    │ 전체 삭제     │
│              │      │ [대화 파일    │     │  txt 첨부)   │    │              │
│ [입력창] [▶] │      │  가져오기]    │     │              │    │              │
└──────────────┘      │ 기억 목록 ▸   │     └──────────────┘    └──────────────┘
                      └──────────────┘
```

- **대화:** 메신저 형태. 열 때 조건이 맞으면 챗봇의 첫 메시지가 먼저 나온다. 답변은 글자가 이어져 나오는 방식으로 표시한다.
- **인물:** 캐릭터 시트 편집, 대화 파일 가져오기, 기억 목록 보기와 삭제. 인물 교체는 "새 인물로 바꾸기"로 하며, 이전 인물의 데이터는 보관된다.
- **내 정보:** 항목별 자유 입력과 txt 첨부.
- **설정:** API 키, 모델 선택, 백업, 삭제.

## 6. 동작 방식

### 6.1 구성 요소

| 요소 | 하는 일 |
|---|---|
| 저장소 | 인물, 기억, 대화, 내 정보, 설정을 기기에 저장하고 꺼낸다 |
| 파일 해석기 | 내보내기 txt를 (날짜, 보낸 사람, 내용) 목록으로 바꾼다 |
| 인물 추출기 | 메시지 목록에서 캐릭터 시트 초안, 말투 예시, 기억을 만든다 |
| 기억 검색기 | 지금 대화와 관련된 기억을 골라낸다 |
| 프롬프트 조립기 | 인물 설정, 내 정보, 기억, 최근 대화를 모델에 보낼 형태로 합친다 |
| 모델 연결부 | AI 제공사 API를 호출한다. 제공사를 바꿔 끼울 수 있는 공통 형태를 가진다 |
| 대화 정리기 | 대화가 끝난 뒤 요약과 새 기억을 만든다 |
| 첫 마디 생성기 | 앱을 열 때 먼저 걸 말을 만든다 |

각 요소는 화면과 분리된 순수한 기능으로 만들어 따로 시험할 수 있게 한다.

### 6.2 저장 데이터

- **인물:** 식별자, 캐릭터 시트 항목(이름, 관계, 성격, 말투, 배경 설정, 자유 메모), 말투 예시(실제 메시지 발췌 최대 30개), 현재 사용 여부
- **기억:** 인물 식별자, 종류(파일에서 추출 / 대화에서 생성), 내용 한두 문장, 관련 날짜, 핵심어, 생성 시각
- **이어갈 화제:** 인물 식별자, 내용("금요일에 면접 결과 나온다"), 생성 시각, 사용 여부
- **대화 메시지:** 인물 식별자, 보낸 쪽, 내용, 시각
- **대화 요약:** 인물 식별자, 지금까지의 누적 요약
- **내 정보:** 항목 이름과 내용
- **설정:** API 키, 제공사, 모델 이름

모든 기억, 대화, 요약은 인물 식별자로 구분한다. 인물 교체와 2차의 다중 인물은 이 구분만으로 가능하다.

### 6.3 대화 파일 가져오기

1. 사용자가 txt 파일을 고른다.
2. 파일 해석기가 형식을 판별해 메시지 목록으로 바꾼다. **[사용자 결정]** 1차는 카카오톡 내보내기 형식(안드로이드, 아이폰, PC)과 왓츠앱 내보내기 형식(안드로이드, 아이폰)을 지원한다. 앱마다 해석기를 따로 두고 공통된 메시지 목록 형태로 돌려주며, 다른 채팅앱은 해석기를 추가하는 방식으로 확장한다.
3. 대화 참여자 목록을 보여주고, 사용자가 "인물이 될 사람"과 "나"를 고른다. 단체방이면 나머지 참여자의 메시지는 맥락으로만 쓴다.
4. 메시지 수와 예상 비용을 보여주고, 사용할 기간을 고르게 한다(전체 / 최근 1년 / 최근 3개월).
5. 인물 추출기가 메시지를 일정 분량씩 나눠 모델에 보내 각 구간의 말투 특징과 사건을 뽑고, 마지막에 하나로 합쳐 캐릭터 시트 초안, 말투 예시, 기억 목록을 만든다. 진행률을 표시한다.
6. 사용자가 초안을 확인하고 고친 뒤 저장한다. 이미 작성한 시트가 있으면 덮어쓰지 않고 항목별로 "기존 유지 / 새 내용 사용"을 고르게 한다.

중간에 실패하면 완료된 구간은 보존하고 이어서 재시도할 수 있게 한다. 원본 txt는 저장하지 않고 추출 결과만 저장한다.

### 6.4 답변 만들기

사용자가 메시지를 보내면 다음 순서로 모델에 보낼 내용을 조립한다.

1. 인물 지시문: 캐릭터 시트 전체, 말투 예시, "이 인물로서만 말한다"는 역할 지시
2. 내 정보 전체
3. 누적 대화 요약
4. 관련 기억: 기억 검색기가 고른 상위 10개
5. 최근 대화 30개 원문
6. 현재 날짜와 시각

**기억 검색기 [제안]:** 사용자의 최근 메시지와 기억의 핵심어 일치 정도에 최신성을 더해 점수를 매긴다. 의미 기반 검색(임베딩)은 서버나 추가 API가 필요해 1차에서 쓰지 않는다. 검색 품질이 부족하면 2차에서 교체할 수 있도록 검색기는 "질문을 받아 기억 목록을 돌려준다"는 단일한 형태를 가진다.

### 6.5 대화 정리와 먼저 말 걸기

**대화 정리기:** 마지막 메시지 후 앱이 뒤로 가거나 닫힐 때, 그리고 다음에 앱을 열 때 정리되지 않은 대화가 남아 있으면 실행한다. 모델에 한 번 요청해 (1) 누적 요약 갱신 (2) 새 기억 (3) 이어갈 화제를 만든다.

**첫 마디 생성기:** 앱을 열었을 때 마지막 메시지로부터 **[제안]** 1시간 이상 지났으면 실행한다. 입력은 인물, 누적 요약, 사용하지 않은 이어갈 화제, 최근 기억, 현재 시각, 지난 공백의 길이다. 이어갈 화제가 있으면 그것을, 없으면 시간대나 공백 길이에 맞는 말을 건다. 사용한 화제는 사용됨으로 표시해 반복을 막는다.

첫 마디 생성기는 화면과 무관하게 "저장된 데이터와 현재 시각을 받아 메시지 하나를 돌려주는" 기능으로 만든다. 2차에서 서버가 같은 기능을 정해진 시각에 호출하면 알림이 된다.

### 6.6 오류 처리

| 상황 | 처리 |
|---|---|
| API 키 없음 또는 틀림 | 설정 화면으로 안내하는 문구 표시 |
| 네트워크 끊김, 호출 실패 | 메시지 옆에 "다시 보내기" 표시. 사용자 메시지는 보존 |
| 사용량 한도, 요금 문제 | 제공사의 오류 문구를 그대로 표시 |
| 모델이 답변 거절 | 응답을 그대로 표시. 재시도나 우회 없음 |
| 파일 형식을 알 수 없음 | 지원 형식 안내. 아무것도 저장하지 않음 |
| 저장 공간 부족 | 경고 후 백업 내보내기 안내 |
| 대화 정리 실패 | 조용히 넘기고 다음에 앱을 열 때 재시도 |

### 6.7 백업

설정에서 전체 데이터를 파일 하나로 내보내고 가져올 수 있다. **[제안]** API 키는 백업 파일에 넣지 않는다. 브라우저 데이터를 지우면 모든 내용이 사라지므로, 대화 파일 가져오기를 마친 직후 백업을 권하는 안내를 한 번 띄운다.

## 7. 성공 확인 방법

자동 시험:
- 파일 해석기: 카카오톡 세 형식과 왓츠앱 두 형식의 견본 파일에서 날짜, 보낸 사람, 내용이 정확히 나온다. 여러 줄 메시지, 시스템 문구(입장, 사진), 날짜 구분선을 올바로 처리한다. 모르는 형식은 오류로 돌려준다.
- 기억 검색기: 핵심어가 맞는 기억이 위로 오고, 같은 점수면 최근 것이 앞선다.
- 프롬프트 조립기: 여섯 요소가 정해진 순서로 들어가고, 최근 대화가 30개로 잘린다. 다른 인물의 기억이 섞이지 않는다.
- 첫 마디 생성기: 공백 1시간 미만이면 실행하지 않는다. 사용한 화제를 다시 쓰지 않는다.
- 저장소: 인물 교체 후 이전 인물의 데이터가 남아 있고 새 인물과 섞이지 않는다. 백업 파일에 API 키가 없다.
- 모델 연결부는 가짜 응답으로 대체해 시험한다.

직접 확인 (실제 휴대폰에서):
- 홈 화면에 설치되고 주소창 없이 열린다.
- 실제 내보내기 파일을 넣어 시트 초안이 그 사람답게 나온다.
- 며칠에 걸쳐 써보며 2절의 실패 조건 네 가지에 해당하지 않는지 본다.

## 8. 만드는 사람이 정할 것

- 화면의 세부 모양, 색, 글꼴
- 말투와 사건을 뽑는 지시문의 구체적 문구 (실제 파일로 조정)
- 파일을 나누는 구간 크기, 기억 점수의 가중치
- 기술 선택. **[제안]** TypeScript, React, Vite, 기기 저장소는 IndexedDB(Dexie), 시험은 Vitest, 첫 AI 제공사는 Anthropic(Claude). 3절의 브라우저 직접 호출 확인 결과에 따라 제공사는 바뀔 수 있다.

## 9. 작성자가 정한 사항 요약 (검토용)

1. (사용자 결정으로 변경) 1차 지원 형식은 카카오톡과 왓츠앱 내보내기 (6.3)
2. 내 정보와 이력서는 txt와 붙여넣기만, PDF는 2차 (2절)

4. 먼저 말 걸기 기준은 공백 1시간 (6.5)
5. 원본 대화 파일은 저장하지 않고 추출 결과만 저장 (6.3)
6. 백업 파일에 API 키 제외 (6.7)
7. 첫 AI 제공사는 Claude, 기술 구성 (8절)

## 10. 변경 기록

### 2026-11-13: Google(Gemini) 제공사 추가

- **[사용자 결정]** Google AI Studio에서 발급한 API 키도 쓸 수 있게 한다.
- 설정 화면에 "AI 제공사" 선택(Anthropic, Google)을 둔다. 제공사별 키와 모델 이름은 기기에 따로 저장해, 다시 바꿔도 다시 넣지 않는다.
- 3절의 "기기 밖으로 나가는 것은 AI 모델 API 호출뿐"은 유지하며, 호출 대상은 고른 제공사 한 곳이다 (`api.anthropic.com` 또는 `generativelanguage.googleapis.com`).
- Google 기본 모델은 `gemini-3.8-flash`. 키는 주소가 아닌 요청 헤더(`x-goog-api-key`)로 보낸다.
- Gemini가 답변을 차단하면 사유를 그대로 보여주고 재시도하지 않는다 (3절의 거절 처리와 같은 원칙).
- 백업 가져오기는 기기의 AI 설정(제공사, 키, 모델)을 건드리지 않는다. 이전에는 백업의 모델 이름으로 바꿨다.
- **[제안]** Gemini는 자체 추론에 출력 한도를 쓰므로 요청한 한도에 8,192 토큰의 여유를 더한다.
